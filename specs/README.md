# specs

アプリを修正するときの管理資料。修正ごとにフォルダを分ける。サイトには載せない。現在の仕様の参照先は `AGENTS.md` で、この配下は参照先にしない。

## 決まり

- 画面、操作、保存、問題データ、公開のしかたを変える依頼は、実装の前に案件フォルダを作る。作り方は `_template/README.md` を写す。
- フォルダ名は `NNNN-短い英語の名前`。`NNNN` は、すでにある案件番号の最大に 1 を足した 4 桁。
- 文書には、目的、決めたこと、触るファイル、手順、確認を書く。確認は Markdown のチェックボックスにして、確認した結果をその行に書き足す。
- 製品の仕様を変えるときは、実装の前に `AGENTS.md` を更新する。
- レビューで出た直しは、その案件のフォルダで扱う。完了した案件への別の依頼は、新しい番号のフォルダにする。状況が「完了」になったあとは、そのフォルダの文書を修正しない。
- 公開は `main` への push で行う。区切りになる版には `vX.Y.Z` のタグを付ける。変更履歴は git と、この配下の案件で足りるので、CHANGELOG は作らない。

## 状況

| 状況 | 意味 |
| --- | --- |
| 文書作成 | 文書を書いていて、実装には入っていない |
| 着手 | 実装に入っている |
| レビュー待ち | 実装が終わり、利用者のレビューを待っている |
| 確認中 | レビューを通過し、確認を進めている |
| 完了 | 確認が終わった |
