# 初回公開に向けた問題データの作成

## 状況

確認中（状況の意味は `../README.md`）。17回すべての問題文と解説を作成し、別担当のレビューで全問を確認済みにした。残りは、利用者による抜き取り確認である。

## 目的

17回分の問題画像、正解、問題文のテキスト、解説を作り、一覧に出せる状態にする。アプリの実装は、この案件の試作回（令和7年度秋期）ができた時点で並行して進める（アプリの画面は `AGENTS.md` が正）。

## 対象

17回（`scripts/exams.py`）。平成28年度春期は問2を収録しないので、全体で 424 問になる。

## 手順

### 1. 画像と正解（自動）

1. `scripts/fetch_sources.py` で PDF を取得する。
2. `scripts/cut_questions.py` で問題画像を切り出す。警告が出た問は画像を開いて確認する。
3. `scripts/extract_answers.py` で正解を反映する。解答例に正解がない問は、IPA の注記を確認して `scripts/exams.py` の `EXCLUDED` に入れる。
4. `scripts/validate_content.py` で整合を確認する。

### 2. 問題文の起こしと解説（回ごと）

回ごとに、作成とレビューを別の作業者が行う。作成した同じ作業者が、その問を「確認済み」にしない。

1. **作成**: 問題画像を1問ずつ開き、`stem`、`choices`、`visuals`、`explanation` を `content/<id>.json` に書く。書いた問は `status/<id>.json` で「作成済み」にする。
2. **レビュー**: 「作成済み」の問を、問題画像・正解（`answer`）と照合する。観点を満たす問は「確認済み」、足りない問は「要見直し」にして、`note` に観点の番号と理由を書く。
3. **直し**: 「要見直し」の問だけを直し、「作成済み」に戻してレビューへ出す。
4. 25問（平成28年度春期は24問）がすべて「確認済み」になったら、`scripts/validate_content.py --complete` を通し、`scripts/build_index.py` で一覧に載せる。

進め方は、先に令和7年度秋期の1回分を最後まで作り、利用者が文章の質を確認してから、残り16回に進む。問題があったときは、この文書の観点を直してから進める。

進捗は `status/<回の id>.json` に置く。`content/` には置かない（状態とコメントをサイトに出さないため）。形は次のとおり。

```json
{
  "examId": "2025-r07-aki",
  "items": [
    { "no": 1, "state": "確認済み", "note": "" }
  ]
}
```

`state` は `未着手`、`作成済み`、`要見直し`、`確認済み` のどれか。`note` はレビューの指摘と、作成側の補足（断定を避けた点、元の想定より長くした理由など）を書く。

## 問題文の起こしの観点

1. `stem` が、図と表以外の設問文と一致する。句読点と用語の文字は画像に合わせる。折り返しの改行は詰めてよい。
2. `choices` のア〜エが、画像の各肢と一致する。肢の取り違えがない。
3. 表は Markdown の表にして `stem` または `choices` に含め、`visuals` に `table` を入れる。セルの結合や一つのセルの中の複数行は、結合している範囲を文で補う。
4. 図・グラフ（アローダイアグラム、ガントチャート、EVM のグラフなど）は文字にせず、`visuals` に `figure` を入れる。図でも表でもない画像は `image` とする。該当がなければ `visuals` は空配列にする。図の問は、解説を書くときもレビューのときも画像を開く。
5. `no`、`answer`、`image` は変えない。

## 解説の観点

公式資料に解説はない。元の資料と照らす対象がないので、正解と問題画像を根拠に書く。新しく足す説明は、根拠を確認できたものだけ書く。

1. 問題文の言い換えだけで終わらせない。用語の意味、仕組み、背景、具体例のうち、正誤の理由に必要なものを書く。問題文に書いてあることや、容易に想像できる説明は繰り返さない。
2. 各肢に対応する一般的な用語、手法、契約形態、理論があれば、それを特定して特徴を書く。同じ理由で誤りになる肢は、まとめて書いてよい（その場合も、各肢が何にあたるかは書く）。肢の本文が用語の名前だけのときは、その意味を短く書く。意味が問題文や肢の本文にすでにあるときは、名前を特定するだけで繰り返さない。
3. 肢全体に対応する一般的な概念がなければ、その旨を書く。記述の一部が既存の概念に似ているときは、類似点と相違点を書く。
4. 誤りの肢は、どの記述が、どの概念のどの特徴と食い違うかを書く。必要なときは短い事例や数値を使う。計算で値が一つに定まる問（所要日数、金額など）は、正解の計算だけを書き、誤答の解説は書かない。順序を選ぶ問、グラフを選ぶ問、最大または最小を選ぶ問は、正解の根拠だけでは各肢が誤りな理由が分からないので、各肢がどこで食い違うか（順序の入れ替わり、グラフの形など）、または各肢の結果を書く。
5. 用語、制度、契約の説明が正確かを確認する。似た概念を混同しない。一般的な傾向を、例外のない規則として書かない。根拠を確認できない法令や契約は断定しない。
6. 過去問は出題当時の資料に基づく。PMBOK ガイドの版（第4版〜第7版）や JIS Q 21500、法令は改訂されている。問題が版を明記しているときは、その版の用語で書く。現行と食い違うときだけ、その旨を一言添える。
7. 長さは、4肢の要点が分かる程度（目安は 150〜400 字）にする。肢が短く、書くことが少ない問は、目安より短くてよい（ただし観点1〜4を満たす）。目安を超えて長くなる理由があるとき（各肢の結果を比べる、など）は、`note` に書く。
